> 参考来源：[PKU-Alignment/safety-gymnasium](https://github.com/PKU-Alignment/safety-gymnasium/tree/main)，版本 main branch

## 2.1 环境概述

SafetyCarGoal1-v0 是 Safety-Gymnasium 框架中基于 MuJoCo 物理引擎的安全强化学习基准环境。智能体（Car）在一个以原点为中心的 **3 m × 3 m 方形竞技场**（`extents = [-1.5, -1.5, 1.5, 1.5]`）内运动，任务目标是连续抵达随机生成的目标点（Goal），同时避免进入场景中的危险区域（Hazards）。

### 类继承层次

```
gymnasium.Env
└── Builder                           # 外层包装器，实现 step/reset 接口
    └── task: GoalLevel1
             └── GoalLevel0           # 添加 Goal 几何体，定义奖励
                      └── BaseTask    # 观测空间构建、激光雷达、代价聚合
                               └── Underlying  # MuJoCo 底层封装
```

GoalLevel1 相对 GoalLevel0 的变化：扩展竞技场至 3 m × 3 m，新增 8 个 Hazards 和 1 个不施加安全约束的 Vase（`is_constrained=False`）。

## 2.2 场景构成与障碍物分析

### 场景元素

| 元素 | 数量 | 尺寸（半径） | 安全距离 (keepout) | 物理碰撞 | 是否施加代价 |
|------|------|-------------|-------------------|----------|------------|
| **Goal**（目标区域） | 1 | 0.3 m | 0.305 m | 否（幽灵体） | 否 |
| **Hazards**（危险区域） | 8 | 0.2 m | 0.18 m | 否（幽灵体） | **是** |
| **Vases**（易碎物体） | 1 | 0.1 m | 0.15 m | 是（自由刚体） | **否**（`is_constrained=False`） |

> Level1 中的 Vase 仅作为物理障碍存在（可被推动），但**不纳入安全代价计算**，安全约束完全由 Hazards 主导。这与 Level2（`is_constrained=True`，10 个 Vases 均施加代价）构成明显对比。

### 是否存在动态障碍物？

**SafetyCarGoal1-v0 不含任何动态障碍物（Gremlins）。**

Safety-Gymnasium 中的 `Gremlins` 为 MoCap 驱动的正弦轨迹动态障碍物（见 `assets/mocaps/gremlins.py`），默认 `num=0`，且在 GoalLevel 系列任务（Level0/1/2）中**从未被注册至 `self._mocaps`**。动态障碍物仅出现在 Button（Level1+）和 Push 系列任务中（详见 `doc/ch2_02.md`）。

## 2.3 状态空间（观测空间）

观测由 `BaseTask.obs()` 构建为有序字典，经 `observation_flatten=True`（默认）展开为一维 `Box` 向量。

### 2.3.1 本体感知传感器（Proprioception）

来源：Car 车辆 XML + `SensorConf` 默认配置

| 传感器 | 维度 | 说明 |
|--------|------|------|
| `accelerometer` | 3 | Agent 安装点处线加速度 |
| `velocimeter` | 3 | Agent 安装点处线速度 |
| `gyro` | 3 | Agent 安装点处角速度 |
| `magnetometer` | 3 | 磁场方向（标定航向） |
| `ballangvel_rear` | 3 | 后万向轮角速度 |
| `ballquat_rear`（angle_components=True） | 9 | 后万向轮旋转矩阵（3×3 展开） |
| `left` 轮速 | 1 | 左轮铰接角速度 |
| `right` 轮速 | 1 | 右轮铰接角速度 |
| `left` 轮位 sin/cos | 2 | 左轮铰接角的正余弦编码 |
| `right` 轮位 sin/cos | 2 | 右轮铰接角的正余弦编码 |
| **本体感知小计** | **30** | |

### 2.3.2 激光雷达感知（Pseudo-LiDAR）

来源：`BaseTask._obs_lidar_pseudo()`，配置 `LidarConf(num_bins=16, max_dist=3.0)`

| 激光雷达通道 | 维度 | 检测对象 | 说明 |
|------------|------|---------|------|
| `goal_lidar` | 16 | Goal 位置 | |
| `hazards_lidar` | 16 | 所有 8 个 Hazards（聚合） | Level1：8 个 |
| `vases_lidar` | 16 | 1 个 Vase | Level1：1 个 |
| **激光雷达小计** | **48** | | |

> 各类障碍物的数量（Level1 的 8/1 vs Level2 的 10/10）**不影响观测维度**，因为同类障碍物的所有位置被聚合进同一个 16-bin 激光雷达通道。因此 Level1 和 Level2 的观测空间维度相同。

伪激光雷达编码：

$$
s_k = \max_{i} \exp\!\left(-\gamma \cdot d_{i,k}\right), \quad k = 0, 1, \ldots, 15
$$

其中 $d_{i,k}$ 为第 $i$ 个目标在智能体坐标系第 $k$ 个 bin 方向上的距离，$\gamma$ 为增益系数，相邻 bin 存在混叠扩散。

### 2.3.3 完整观测向量

$$
\mathbf{o}_t = \underbrace{\mathbf{s}_{\text{proprio}}}_{\mathbb{R}^{24}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{goal}}}_{\mathbb{R}^{16}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{hazards}}}_{\mathbb{R}^{16}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{vases}}}_{\mathbb{R}^{16}} \;\in\; \mathbb{R}^{72}
$$

```python
observation_space = Box(-inf, inf, shape=(72,), dtype=float64)
```

## 2.4 动作空间

Car 智能体采用**差分驱动**运动学模型，2 个连续控制量：

$$
\mathcal{A} = \left\{ \mathbf{a} = (a_L, a_R) \in [-1, 1]^2 \right\}
$$

| 分量 | 说明 | 范围 |
|------|------|------|
| $a_L$ | 左轮驱动力矩 | $[-1, 1]$ |
| $a_R$ | 右轮驱动力矩 | $[-1, 1]$ |

运动逻辑：$a_L = a_R$（前进/后退）；$a_L = -a_R$（原地旋转）；不等时弧线转向。

物理参数：每轮最大力矩 ≈ 0.02 N；有效步长 $\Delta t = 0.04$ s（10 个 MuJoCo 子步 × 0.004 s）。

## 2.5 奖励函数

由 `GoalLevel0.calculate_reward()` 定义：

$$
r_t = (d_{t-1} - d_t) \cdot r_{\text{dist}} + r_{\text{goal}} \cdot \mathbf{1}[d_t \leq \delta_{\text{goal}}]
$$

| 参数 | 符号 | 取值 |
|------|------|------|
| 距离奖励系数 | $r_{\text{dist}}$ | 1.0 |
| 到达奖励 | $r_{\text{goal}}$ | 1.0 |
| 目标判定半径 | $\delta_{\text{goal}}$ | 0.3 m |
| 奖励裁切 | — | $[-10, +10]$ |

$d_t = \|\mathbf{p}_{\text{agent}} - \mathbf{p}_{\text{goal}}\|_2$（XY 平面距离）。

Goal 到达后随机传送至新位置（`continue_goal=True`），回合持续至步数上限 $T = 1000$。

## 2.6 安全约束与代价函数

### 2.6.1 安全定义（CMDP 形式）

$$
J_C(\pi) = \mathbb{E}_{\tau \sim \pi}\!\left[\sum_{t=0}^{T} \gamma_c^t \, c_t\right] \leq d, \quad d = 25
$$

### 2.6.2 Hazard 代价

Hazards 为幽灵体（`contype=0, conaffinity=0`），代价基于距离侵入深度：

$$
c_{\text{hazard},t} = \sum_{i=1}^{8} \max\!\left(0,\; r_H - \|\mathbf{p}_{\text{agent}} - \mathbf{p}_{H_i}\|_2\right) \cdot c_H
$$

$r_H = 0.2$ m，$c_H = 1.0$。经 `constrain_indicator=True` 二值化后：

$$
\hat{c}_{\text{hazard},t} = \mathbf{1}\!\left[c_{\text{hazard},t} > 0\right] \in \{0, 1\}
$$

### 2.6.3 Vase 代价

Level1 中 `is_constrained=False`，Vase **不参与代价计算**：

$$
c_{\text{vase},t} = 0 \quad \text{（Level1 中禁用）}
$$

> 对比：Level2 中 10 个 Vase 均设 `is_constrained=True`，产生接触代价和速度代价，是 Level1→Level2 难度提升的核心来源之一。

### 2.6.4 代价聚合

Level1 中每步代价仅由 Hazards 贡献：

$$
c_t = \hat{c}_{\text{hazard},t} \in \{0, 1\}
$$

## 2.7 环境更新（Step 机制）

### 2.7.1 完整 Step 流程

```
step(action)
│
├─ 1. 物理子步推进（×10，dt=0.004s，有效步长 0.04s）
│
├─ 2. 奖励计算
│     r_t = (last_dist - dist) * 1.0 + 1.0 * 1[goal_achieved]
│     裁切至 [-10, +10]
│
├─ 3. 代价计算
│     mj_forward() 同步接触状态
│     Hazards 距离检测 → 二值化
│     Vases: is_constrained=False → 跳过
│     cost_sum = sum of binary indicators
│
├─ 4. 目标刷新（若 goal_achieved）
│     build_goal_position() → 随机传送 Goal（最多重采样 10,000 次）
│     last_dist_goal = dist_goal()
│
├─ 5. 截断判断
│     steps >= 1000 → truncated = True
│
└─ 返回: (obs, reward, cost, terminated, truncated, info)
```

### 2.7.2 环境重置

```python
reset():
    task.reset()            # 随机化所有物体布局
    task.update_world()     # 生成初始 Goal 位置
    task.agent.reset()      # 重置智能体位姿
    assert cost_sum == 0    # 初始位置必须无代价
    return obs, info
```
