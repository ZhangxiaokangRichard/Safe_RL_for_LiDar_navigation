## 2.1 环境概述

SafetyButtonGoal1-v0 是一个基于 MuJoCo 物理引擎的序列按键任务，智能体（Car）在 **3 m × 3 m 方形竞技场**（`extents = [-1.5, -1.5, 1.5, 1.5]`）内运动，需要识别并按下当前目标按钮（Goal Button），同时避免：
- 踩入静态危险区域（Hazards）
- 被动态障碍物（Gremlins）碰撞
- 误触非目标按钮（Wrong Buttons）

### 类继承层次

```
gymnasium.Env
└── Builder                              # 外层包装器，step/reset 接口
    └── task: ButtonLevel1
             └── ButtonLevel0 / ButtonBase  # 定义奖励、按钮机制
                      └── BaseTask          # 观测空间、激光雷达、代价聚合
                               └── Underlying  # MuJoCo 底层封装
```

## 2.2 场景构成

### 障碍物配置（ButtonLevel1）

| 元素 | 数量 | 尺寸 | 安全距离 (keepout) | 类型 | 是否施加代价 |
|------|------|------|-------------------|------|------------|
| **Buttons**（按钮） | 4 | 0.1 m | 0.3 m | 静态幽灵体 | 是（误触） |
| **Goal Button**（目标按钮） | 1 of 4 | — | — | 动态标记 | 否（应按） |
| **Hazards**（危险区域） | 4 | 0.2 m | 0.18 m | 幽灵体 | 是 |
| **Gremlins**（动态障碍物） | 4 | 0.1 m | 0.4 m | MoCap 刚体 | 是 |

> ButtonLevel2 在 Level1 基础上将 Hazards 增至 8 个、Gremlins 增至 6 个，竞技场扩大至 3.6 m × 3.6 m。

### 动态障碍物 —— Gremlins

**Gremlins 是 Safety-Gymnasium 中唯一自主运动的障碍物类型。**

与 Goal 系列任务中的 Vases（被动刚体，仅因碰撞而移动）不同，Gremlins 由 MuJoCo **MoCap（运动捕捉体）**驱动，按预定轨迹周期性运动，完全不受物理力影响。

## 2.3 状态空间（观测空间）

观测展平为一维向量，结构与 CarGoal 系列相同：**本体感知 + 多类激光雷达**。

### 2.3.1 本体感知传感器（同 CarGoal，30 维）

| 传感器 | 维度 |
|--------|------|
| accelerometer / velocimeter / gyro / magnetometer | 3 × 4 = 12 |
| ballangvel_rear | 3 |
| ballquat_rear（旋转矩阵） | 9 |
| left/right 轮速 + sin/cos | 2 + 4 = 6 |
| **小计** | **30** |

### 2.3.2 激光雷达通道（Button 任务特定）

| 通道 | 维度 | 检测目标 | 特殊行为 |
|------|------|---------|---------|
| `buttons_lidar` | 16 | 所有 4 个 Buttons | **按下目标按钮后归零** 10 步 |
| `hazards_lidar` | 16 | 所有 4 个 Hazards | — |
| `gremlins_lidar` | 16 | 所有 4 个 Gremlins | — |
| `goal_lidar` | 16 | 目标按钮位置（Goal 标记） | — |
| **小计** | **64** | | |

### 2.3.3 完整观测向量

$$
\mathbf{o}_t = \underbrace{\mathbf{s}_{\text{proprio}}}_{\mathbb{R}^{30}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{buttons}}}_{\mathbb{R}^{16}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{hazards}}}_{\mathbb{R}^{16}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{gremlins}}}_{\mathbb{R}^{16}} \;\Big\|\; \underbrace{\mathbf{l}_{\text{goal}}}_{\mathbb{R}^{16}} \;\in\; \mathbb{R}^{94}
$$

> **关键差异**：按下目标按钮后，`buttons_lidar` 在接下来 10 步被强制置零（`timer != 0` 期间），智能体无法看到任何按钮，直至新目标被宣布。这防止智能体在重采样期间预先导航至下一目标。

## 2.5 Gremlins 动态运动机制

### 运动方程

每个환境步 `specific_step()` 调用 `gremlins.move()`，所有 Gremlins 按统一相位在各自初始位置附近做**圆周运动**：

$$
\begin{aligned}
x_i(t) &= x_{i,0} + r_{\text{travel}} \cdot \sin(t_{\text{sim}}) \\
y_i(t) &= y_{i,0} + r_{\text{travel}} \cdot \cos(t_{\text{sim}})
\end{aligned}
$$

其中：
- $t_{\text{sim}}$：MuJoCo 仿真时间（秒），所有 Gremlins **共享同一相位**
- $r_{\text{travel}} = 0.35$ m：圆周运动半径
- $(x_{i,0}, y_{i,0})$：第 $i$ 个 Gremlin 的随机初始放置位置

### 代码实现（`gremlins.py`）

```python
def move(self):
    phase = float(self.engine.data.time)
    for i in range(self.num):
        target = np.array([np.sin(phase), np.cos(phase)]) * self.travel
        pos = np.r_[target, [self.size]]
        self.set_mocap_pos(f'gremlin{i}mocap', pos)
```

### MoCap 驱动特性

- Gremlins 使用 MuJoCo **MoCap** 机制（运动学体）：位置由代码直接设定，**不受任何物理力影响**
- 智能体撞到 Gremlin 时，智能体本身会受到物理反作用，但 Gremlin 不改变轨迹
- 圆周半径固定，所有 Gremlins 同步运动（非独立相位），构成可预测但需规避的周期性危险区

## 2.6 奖励函数

由 `ButtonBase.calculate_reward()` / `ButtonLevel0.calculate_reward()` 定义，结构与 GoalTask 完全相同：

$$
r_t = (d_{t-1} - d_t) \cdot r_{\text{dist}} + r_{\text{goal}} \cdot \mathbf{1}[\text{goal\_achieved}]
$$

| 参数 | 取值 |
|------|------|
| $r_{\text{dist}}$ | 1.0（向目标按钮的距离塑形） |
| $r_{\text{goal}}$ | 1.0（成功按下目标按钮的稀疏奖励） |

其中 $d_t = \|\mathbf{p}_{\text{agent}} - \mathbf{p}_{\text{goal\_button}}\|_2$（XY 平面距离，目标按钮随机变化）。

**与 CarGoal 的奖励差异**：Goal 位置不再是空间中的任意点，而是 4 个固定按钮中随机选定的一个。

## 2.7 安全约束与代价函数

### 2.7.1 Hazard 代价（同 CarGoal）

$$
c_{\text{hazard},t} = \mathbf{1}\!\left[\sum_{i=1}^{4}\max(0,\ r_H - d_i) > 0\right]
$$

$r_H = 0.2$ m，经 `constrain_indicator` 二值化。

### 2.7.2 Gremlin 接触代价

代价基于 **MuJoCo 物理接触事件**（而非距离），每发生一次 Gremlin 与智能体的接触即累加：

$$
c_{\text{gremlin},t} = \sum_{\text{contact}} \mathbf{1}\!\left[\text{geom}_1 \in \text{gremlin} \land \text{geom}_2 \in \text{agent}\right] \cdot c_{\text{contact}}
$$

经 `constrain_indicator` 二值化：$\hat{c}_{\text{gremlin},t} \in \{0, 1\}$

| 参数 | 取值 |
|------|------|
| `contact_cost` | 1.0 |
| `is_constrained` | True（Level1+） |

### 2.7.3 误触按钮代价

当智能体触碰**非目标按钮**时产生代价：

$$
c_{\text{button},t} = \sum_{j \neq \text{goal}} \mathbf{1}\!\left[\text{contact}(\text{button}_j, \text{agent}) \land \text{timer} = 0\right]
$$

注意：`timer != 0`（目标按下后的 10 步缓冲期）内，误触代价**暂时禁用**，与激光雷达归零保持同步。

### 2.7.4 代价聚合（Buffer 期间）

```
cost_sum = hat_c_hazard + hat_c_gremlin + hat_c_button
```

三类代价相互独立，均经二值化，`cost_sum` 为 0\~3 之间的整数。

## 2.8 环境更新（Step 机制）

### 2.8.1 完整 Step 流程

```
step(action)
│
├─ 1. specific_step()
│     gremlins.move()      # 更新所有 Gremlins 位置（MoCap 设定）
│     buttons.timer_tick() # timer = max(0, timer - 1)
│
├─ 2. 物理子步推进（×10，dt=0.004s）
│
├─ 3. 奖励计算
│     r_t = (last_dist_button - dist_button) * 1.0
│           + 1.0 * 1[goal_achieved]
│
├─ 4. 代价计算
│     mj_forward() 同步接触
│     Hazards: 距离检测 → 二值化
│     Gremlins: 接触检测 → 二值化
│     Buttons: 误触检测（仅 timer==0 时激活） → 二值化
│     cost_sum = sum(hat_c)
│
├─ 5. 目标切换（若 goal_achieved）
│     build_goal_button()   # 重新随机选择目标按钮
│     reset_timer()         # timer = resampling_delay (10)
│     → buttons_lidar 归零（接下来 10 步）
│
├─ 6. 截断：steps >= 1000
│
└─ 返回: (obs, reward, cost, terminated, truncated, info)
```

### 2.8.2 目标按钮切换机制

`build_goal_button()` 在 4 个按钮中随机选择一个新的目标按钮（排除刚刚按下的那个），并将 Goal 标记（可见球体）移动至新目标按钮位置，同时启动 `timer=10` 的盲视缓冲期。

```
Timer 状态对环境行为的影响：

timer > 0（缓冲期）：
  ├─ buttons_lidar = [0, 0, ..., 0]   # 按钮对智能体不可见
  └─ 误触代价禁用（constraints_active = False）

timer = 0（正常期）：
  ├─ buttons_lidar = 正常激光雷达信号
  └─ 误触代价启用
```

## 2.9 与 CarGoal1 的关键对比

| 维度 | SafetyCarGoal1-v0 | SafetyButtonGoal1-v0 |
|------|------------------|---------------------|
| 任务类型 | 连续导航至随机点 | 序列按键（随机目标按钮） |
| 动态障碍物 | **无** | **4 个 Gremlins（圆周运动）** |
| 静态危险 | 8 Hazards | 4 Hazards |
| 误触惩罚 | 无 | 误触非目标按钮 |
| 目标刷新 | 任意空间位置 | 4 个固定按钮中随机选一 |
| 观测维度 | 78 | 94 |
| 代价类型 | Hazard only | Hazard + Gremlin + Button |
| 感知盲视 | 无 | 每次按下后 10 步 buttons\_lidar 归零 |
| 难度特征 | 空间覆盖 | 时序规划 + 动态规避 |
