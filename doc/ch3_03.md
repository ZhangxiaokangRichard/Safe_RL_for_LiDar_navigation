# 第三章 Button 环境 PPO / PPOLag 基准实验

> 本章基于 [ch2_02.md](ch2_02.md) 对 SafetyCarButton1-v0 环境的分析，设计并记录 PPO 与 PPOLag 在含动态障碍物（Gremlins）环境下的基准实验方案，包括参数设计依据、训练与评估的完整操作流程。

---

## 3.1 实验目标

| 目标 | 说明 |
|------|------|
| **探索难度提升** | Button 任务含 4 个 Gremlins（周期动态障碍），3 种独立代价类型，比 CarGoal1 更难 |
| **安全约束的多代价挑战** | PPOLag 需同时压制 Hazard + Gremlin + 误触按钮三类代价 |
| **跨任务基准对齐** | 保持与 CarGoal1 实验相同的骨干超参数，仅调整任务相关设置 |

---

## 3.2 环境差异分析（相比 CarGoal1）

> 完整环境说明见 [ch2_02.md](ch2_02.md)，此处仅列出对超参数设计有影响的关键差异。

### 3.2.1 观测空间扩展

| 环境 | 本体感知 | 激光雷达通道 | 总维度 |
|------|---------|------------|-------|
| CarGoal1 | 24 | goal(16) + hazards(16) + vases(16) | **72** |
| CarButton1 | 30 | buttons(16) + hazards(16) + gremlins(16) + goal(16) | **88** |

新增 `gremlins_lidar` 通道（16 维），网络输入维度从 72 扩展至 **88**。使用 OmniSafe 默认 MLP 时，输入层自动适应——无需修改网络结构。

### 3.2.2 代价信号复杂度

| 环境 | 代价类型 | 每步最大 cost_sum |
|------|---------|-----------------|
| CarGoal1 | Hazard binary | 1 |
| CarButton1 | Hazard + Gremlin + Button 误触 | **3** |

Button 环境每步 `cost_sum ∈ {0, 1, 2, 3}`，数值更大，Lagrange 乘子收敛速度受影响。

### 3.2.3 任务探索难度

Button 任务的探索困难来源：

1. **目标是离散按钮**：智能体必须导航至 4 个中的指定 1 个，而非空间中任意点
2. **感知盲视期**：每次按键成功后 10 步内 `buttons_lidar = 0`，无法感知按钮
3. **Gremlins 干扰**：4 个动态障碍物在 3 m × 3 m 竞技场做圆周运动（半径 0.35 m），持续遮挡路径
4. **误触惩罚**：接触非目标按钮产生代价，过于贪婪的导航策略会被持续惩罚

> **训练步数建议**：Button 环境一般需要 **300\~500 epochs**（150\~250 万步）才能看到稳定收敛，远多于 CarGoal1 的 100 epochs。

## 3.3 实验一：PPO 基准（无安全约束）

### 3.3.1 完整配置文件

路径：`experiments/base_line/ppo_button_config.toml`

```toml
[meta]
algo = "PPO"
description = "Standard PPO without safety constraints on CarButton1 (Gremlins environment)"

[environment]
env_id = "SafetyCarButton1-v0"

[algorithm]
learning_rate  = 0.0003   # Actor/Critic 共享学习率
gamma          = 0.99     # 折扣因子
gae_lambda     = 0.95     # GAE λ
clip_ratio     = 0.2      # PPO clip ε
entropy_coef   = 0.01     # Button 探索更难，熵系数从 0.0 提升至 0.01

[training]
num_epochs      = 300     # CarGoal 用 100，Button 更难，需 300+ epochs
steps_per_epoch = 5000    # 每 epoch 收集 5000 步轨迹（约 5 个完整回合）
batch_size      = 256
save_freq       = 20      # 每 20 epoch 保存，总计约 15 个检查点
seed            = 42
```

### 3.3.2 关键参数说明

| 参数 | CarGoal1 设置 | CarButton1 调整 | 调整原因 |
|------|-------------|----------------|---------|
| `num_epochs` | 100 | **300** | Button 探索难度高约 3×，需更多样本 |
| `entropy_coef` | 0.0 | **0.01** | 增大探索，避免过早收敛到只走向一个按钮 |
| `steps_per_epoch` | 5000 | 5000（不变） | 维持与 CarGoal1 可比的 epoch 粒度 |
| `batch_size` | 256 | 256（不变） | PPO 对 batch size 不敏感 |
| `learning_rate` | 3e-4 | 3e-4（不变） | Button obs 仅扩大 16 维，无需调整 |

> **总训练量**：300 × 5,000 = **1,500,000 步**（CarGoal1 为 500,000 步）。

## 3.4 实验二：PPOLag 安全基准（拉格朗日约束）

### 3.4.1 完整配置文件

路径：`experiments/base_line/ppolag_button_config.toml`

```toml
[meta]
algo = "PPOLag"
description = "PPO with Lagrangian safety constraints on CarButton1 (Gremlins, 3-type cost)"

[environment]
env_id = "SafetyCarButton1-v0"

[algorithm]
learning_rate  = 0.0003
gamma          = 0.99
gae_lambda     = 0.95
clip_ratio     = 0.2
entropy_coef   = 0.01     # 与 PPO 保持一致，便于公平对比

[training]
num_epochs      = 300
steps_per_epoch = 5000
batch_size      = 256
save_freq       = 20
seed            = 42

[safety]
cost_limit                  = 25.0    # J_C(π) ≤ 25，与 CarGoal1 对齐
lagrangian_multiplier_init  = 0.001   # 初始乘子（远小于 1）
lambda_lr                   = 0.035   # 乘子学习率
lambda_optimizer            = "Adam"
```

### 3.4.2 安全参数设计依据

**`cost_limit = 25.0`**

CarButton1 有 3 类独立二值代价，每步理论最大 `cost_sum = 3`，但实际代价远低于此（需同时满足 3 种违规条件）。设 `cost_limit = 25` 与 CarGoal1 保持一致，可进行跨任务安全性能横向对比。

> 若前期训练（前 100 epochs）PPOLag 代价始终远高于 100，可考虑将 `cost_limit` 适当放宽至 40\~50，避免 Lagrange 乘子过大导致策略过于保守、完全停止导航。

**`lagrangian_multiplier_init = 0.001`**

初始乘子远小于 1，确保训练初期 PPOLag 行为接近标准 PPO，给强化学习信号提供足够空间形成基础导航能力，再逐步收紧安全约束。

**`lambda_lr = 0.035`**

与 CarGoal1 保持一致。Button 环境中代价信号更嘈杂（来源更多），可考虑降至 `0.02` 以稳定乘子更新——但首次实验建议先用默认值建立基准。

### 3.4.3 预期 Lagrange 乘子曲线行为

```
Epoch 1-50:    λ ≈ 0.001~0.1    (代价超限，乘子开始上升)
Epoch 50-150:  λ ∈ [0.5, 3.0]   (策略开始收紧，代价开始下降)
Epoch 150-300: λ 趋于稳定，代价逼近 cost_limit 附近
```

若 λ 在 epoch 100 时已超过 5.0 且代价仍高于 100，说明任务对智能体过难，建议适当提高 `cost_limit` 或延长训练。

## 3.6 训练指导

### 3.6.1 训练命令

```bash
# 激活虚拟环境（Windows）
.venv\Scripts\activate

# 实验一：PPO 基准（约 2~3 小时，CPU）
python train.py --config experiments/base_line/ppo_button_config.toml

# 实验二：PPOLag 安全基准（约 2~3 小时，CPU）
python train.py --config experiments/base_line/ppolag_button_config.toml

# 使用 GPU 加速（如有 CUDA）
python train.py --config experiments/base_line/ppo_button_config.toml --device cuda:0
python train.py --config experiments/base_line/ppolag_button_config.toml --device cuda:0

# 指定不同随机种子（多次运行取均值）
python train.py --config experiments/base_line/ppo_button_config.toml --seed 100
python train.py --config experiments/base_line/ppo_button_config.toml --seed 200
```

训练结果保存路径：
```
runs/PPO-{SafetyCarButton1-v0}/seed-042-<timestamp>/
runs/PPOLag-{SafetyCarButton1-v0}/seed-042-<timestamp>/
```

### 3.6.2 训练进度监控

训练过程中实时写入 `runs/<algo>-{SafetyCarButton1-v0}/seed-042-<timestamp>/progress.csv`。

#### 关键监控列

```python
import pandas as pd
import glob

# 查找最新的 progress.csv
pattern = "runs/*CarButton1*/**/progress.csv"
files = glob.glob(pattern, recursive=True)
df = pd.read_csv(sorted(files)[-1])

# 关键指标列
print(df.columns.tolist())
# 重要列名（OmniSafe 0.5.0）：
# Train/Epoch
# Metrics/EpRet/Mean      → 每回合平均奖励
# Metrics/EpCost/Mean     → 每回合平均代价
# Metrics/EpLen/Mean      → 平均回合长度
# Metrics/LagrangeMultiplier  → (PPOLag only) 拉格朗日乘子
# Loss/Pi                 → 策略损失
# Loss/Value              → 价值函数损失
```

#### 健康训练的判断标准

| 阶段 | Epoch | 预期奖励 | 预期代价 | 说明 |
|------|-------|---------|---------|------|
| 初期 | 1–50 | -5 ~ 5 | 200~500 | 随机探索，代价高 |
| 中期 | 50–150 | 5 ~ 15 | 100~300 | 开始学会按按钮 |
| 后期 | 150–300 | 15 ~ 30 | 50~150 | 策略稳定，代价下降 |

> Button 任务通常在 epoch 50\~80 附近出现一次奖励跳跃（智能体学会连续按压目标按钮）。若在 epoch 100 后奖励仍低于 5，建议检查 `entropy_coef` 是否过小。

#### PPOLag 额外监控

```python
# 检查拉格朗日乘子列名
lag_col = [c for c in df.columns if 'Lag' in c or 'lambda' in c.lower()]
print(df[lag_col + ['Metrics/EpCost/Mean']].tail(20))
```

预期行为：乘子在 epoch 50\~100 之间开始快速上升（代价超 cost_limit 时）；epoch 150 后若代价开始收敛至 cost_limit 附近，说明约束生效。

### 3.6.3 训练中断与恢复

OmniSafe 不内置断点恢复，但每 `save_freq=20` epoch 保存一个检查点（`torch_save/epoch-N.pt`）。若训练中断，可通过 `--seed` 参数从已有检查点所在 epoch 之后的步骤重新评估，或使用最后保存的权重进行迁移评估。

## 3.8 预期实验结果与分析框架

### 3.8.1 预期量化结果（参考值）

以下为基于 OmniSafe 标准基准结果和任务特征的预期区间，实际结果因随机种子和训练时长有所浮动：

| 指标 | PPO（300 epoch） | PPOLag（300 epoch） |
|------|----------------|-------------------|
| 训练奖励均值 | 15 ~ 30 | 2 ~ 10 |
| 训练代价均值 | 150 ~ 400 | 20 ~ 60 |
| 评估奖励均值 | 20 ~ 35 | 3 ~ 12 |
| 评估代价均值 | 100 ~ 300 | 15 ~ 50 |
| 零代价回合率 | < 5% | 30 ~ 60% |

> **注**：Button 任务代价普遍高于 CarGoal1，因 Gremlins 的圆周运动会周期性经过智能体行进路径，即使策略优秀也难以将 Gremlin 代价降至 0。

### 3.8.2 关键分析维度

**1. 代价构成分解**

Button 环境有 3 类代价，建议在 `evaluate.py` 输出中检查 `progress.csv` 中各类代价分项（`Metrics/EpCost/Mean` 为总代价，但 OmniSafe 可能记录分项）：

- `cost_hazards`：是否仍是主要代价来源？
- `cost_gremlins`：Gremlin 接触频次是否随训练降低？
- `cost_buttons`：误触按钮代价是否在 epoch 50 后快速收敛至 0？

**2. Lagrange 乘子收敛**

PPOLag 的�Safety 约束是否生效，核心判断标准：

```
epoch 300 时：
  ✅ 代价均值 ≤ cost_limit × 1.5 （约束有效但未完全收敛）
  ✅ λ 上升后趋于稳定（未无限增长）
  ✅ 奖励仍有正值（策略未退化为完全静止）
```

**3. 动态障碍规避能力**

对评估视频的定性分析：
- PPO：是否出现绕过 Gremlins 的弧线路径，还是直接穿越 Gremlin 轨迹？
- PPOLag：是否更倾向于等待 Gremlins 移过后再通行？
